# Требования к веб-сервису «Media Planner» (Очередь и планирование просмотров/чтения)

## 1. Бизнес-цель (Business Goal)
Создать автономный, портативный веб-сервис для ведения персональной очереди медиа-контента (фильмов, сериалов, книг) и интеллектуального подбора вариантов досуга под имеющееся свободное время пользователя.

Главные бизнес-задачи:
- Исключить необходимость тратить время на долгое решение «что посмотреть или почитать за имеющийся свободный час/два».
- Обеспечить 100% автономность работы приложения с обычной USB-флешки без зависимости от внешних сторонних серверов, подключения к интернету или необходимости установки специализированных СУБД/среды выполнения.

---

## 2. Бизнес-требования (Business Requirements - BR)
- **BR-1 (Портативность и автономность):** Сервис должен запускаться как единый исполняемый файл (single binary) без установки сторонних зависимостей (Node.js, Python, PostgreSQL, Docker и т.д.).
- **BR-2 (Локальность данных):** Все пользовательские данные (учетные записи, медиатека, история и очередь) хранятся в локальном файле базы данных SQLite рядом с бинарным файлом на флешке.
- **BR-3 (Универсальность контента):** Поддержка трех типов контента — фильмы, сериалы и книги.
- **BR-4 (Умное планирование):** Возможность за один клик получить оптимальную подборку контента (или серий/глав), которая точно поместится в зафиксированный временной интервал (например, 45 минут или 2 часа).

---

## 3. Пользовательские требования (User Requirements - UR / Use Cases)
- **UR-1 (Локальная учетная запись):** Пользователь может зарегистрировать персональный аккаунт и входить в систему под своими логином и паролем без интернета.
- **UR-2 (Управление каталогом):** Пользователь может добавлять в свою коллекцию фильмы, сериалы и книги с указанием их временных/объемных характеристик.
- **UR-3 (Управление очередью):** Пользователь может добавлять элементы из каталога в очередь «Хочу посмотреть/почитать», менять их приоритет и отмечать просмотренными/прочитанными.
- **UR-4 (Планирование по времени):** Пользователь указывает имеющееся у него свободное время (в часах/минутах) и получает готовый план просмотра/чтения с детальным распределением хронометража.
- **UR-5 (Прозрачность ошибок):** При возникновении ошибок (неверный пароль, дубликат логина, невалидные длительности) пользователь получает понятно сформулированные уведомления на понятном языке.

---

## 4. Функциональные требования (Functional Requirements - FR)

### 4.1. Аутентификация и пользователи
- **FR-1.1:** Локальная регистрация пользователя (логин, пароль) с надежным хэшированием пароля (bcrypt).
- **FR-1.2:** Авторизация пользователя с выдачей токена сессии (JWT / Cookie).
- **FR-1.3:** Изоляция данных: каждый пользователь видит только свою медиатеку и очередь.

### 4.2. Учет медиа-контента
- **FR-2.1 (Фильмы):** Поля: название, год выпуска, длительность (в минутах), жанр/описание.
- **FR-2.2 (Сериалы):** Поля: название, год выпуска, общее количество серий, средняя продолжительность одной серии (в минутах), количество уже просмотренных серий.
- **FR-2.3 (Книги):** Поля: название, год выпуска, общее количество страниц, средняя скорость чтения (или среднее время на главу/страницу, например 2 мин/страница или общее расчетное время в минутах).

### 4.3. Очередь просмотров (Queue Management)
- **FR-3.1:** Добавление элементов в активную очередь.
- **FR-3.2:** Изменение приоритета (порядка) элементов в очереди.
- **FR-3.3:** Отметка элементов как «В процессе», «Завершено», «Отложено».

### 4.4. Умный планировщик на свободное время (Free Time Planner)
- **FR-4.1:** Пользователь вводит количество доступного времени в минутном или часовом формате.
- **FR-4.2:** Алгоритм формирует оптимальный план досуга из активной очереди:
  - Фильм целиком (если длительность <= свободного времени).
  - Набор N серий сериала (рассчитывается как `количество_серий * средняя_длительность <= свободное_время`).
  - Чтение N страниц книги (рассчитывается исходя из времени на страницу).
- **FR-4.3:** Вывод суммарного времени плана, оставшегося свободного времени и списка конкретных действий (например: «Посмотреть 2 серии сериала X (50 мин) + 1 короткометражный фильм Y (20 мин)»).

### 4.5. Обработка ошибок (Error Handling)
- **FR-5.1:** Единый формат ответа об ошибках API `{ "error": true, "code": "INVALID_INPUT", "message": "Человекочитаемое описание" }`.
- **FR-5.2:** Валидация входных данных на бэкенде и фронтенде (запрет отрицательного времени, пустых названий и т.д.).

---

## 5. Требования к портативности и запуску с флешки (Portability Requirements)
- **PR-1:** Приложение собирается в единый самодостаточный бинарный файл, содержащий внутри себя скомпилированный фронтенд (через `go:embed`).
- **PR-2:** СУБД SQLite запускается в файловом режиме (файл `data.db` создается локально в папке запуска бинарника).
- **PR-3:** Запуск приложения осуществляется двойным кликом / одной командой в терминале, после чего в браузере автоматически или по адресу `http://localhost:8080` доступен веб-интерфейс.
